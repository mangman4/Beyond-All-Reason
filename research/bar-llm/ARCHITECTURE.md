# 구현 구조

- `bar_duel/run.py`: BAR 모드 설치, 엔진 실행, 팀별 비동기 요청, 관전 HTTP 서버, 결과 기록.
- `duel.lua`, `tactics.lua`: 팀별 관측과 가능한 행동, 게임 상태 변화, 명령 재검증. 최근 목격 정보는 최대 120초이며 전체 맵 관측을 제공하지 않습니다.
- `bridge_widget.lua`: 게임과 Python 사이 로컬 연결.
- `network.py`: Cloud/Local Ollama 스트림 처리. 요청 프로세스를 분리하여 시간 제한 시 종료합니다. 응답 원문과 사고 내용은 저장하지 않습니다.
- `swarm.py`: LangGraph 기반 경제 → 생산 → 전투 → 필요 시 조정. 역할별 후보를 제한하고 전체 사이클 45초, 개별 역할 12초의 한도를 적용합니다.
- `assisted.py`: 짧은 자원·진행 작업·위협·후보와 최근 결과를 제공하는 assisted-v2-air 인터페이스.
- `direct.py`, `direct.lua`: 유닛·좌표 직접 명령 검증과 실행. 한 판단 최대 3개 명령, 명령당 최대 8개 유닛. 직접 제어는 실험 기능입니다.
- `dashboard.html`: Cloud/Local 기록을 분리하고 역할별 진행·지연·오류를 표시합니다.
- `batch.py`, `analysis.py`: 위치 교대 실험, 조건별 결과 집계. 시간 상한 종료 및 실행 오류를 승패와 구분합니다.

두 팀 모두 동일 제어 인터페이스로 비교해야 합니다. 현재 비교는 모델 크기뿐 아니라 Cloud/Local 하드웨어, 호출 횟수와 역할 구조도 달라집니다. 군집의 순수 효과는 동일 로컬 모델 단일 실행과 군집 실행을 별도로 비교해야 합니다. 게임 난수는 고정하지 않았으며 위치 교대만으로 모든 편향이 제거되지는 않습니다.

항공 공장과 항공 생산은 생산 역할, 대공 시설·항공 임무는 전투 역할에 배정합니다. 관측에는 지상/항공 병력 수와 현재 보이는 적 항공 전력 수가 포함됩니다. 기존 지상 명령에서 항공기를 제외하고 항공 명령에서 지상군·건설기를 제외합니다.
